C++ 智能指针是 `<memory>` 中基于 **RAII** 的类模板，用来自动管理动态分配对象的生命周期，避免手动 `new/delete` 导致的内存泄漏、重复释放等问题。现代 C++ 中，智能指针应作为管理动态对象生命周期的默认工具。

## 一、三种主要智能指针

| 智能指针              | 所有权 | 是否可拷贝  | 主要用途                   |
| ----------------- | --- | ------ | ---------------------- |
| `std::unique_ptr` | 独占  | 否，只能移动 | 默认首选，独占资源              |
| `std::shared_ptr` | 共享  | 是，引用计数 | 多个对象共享同一资源             |
| `std::weak_ptr`   | 不拥有 | 是      | 观察 `shared_ptr`，打破循环引用 |

> `std::auto_ptr` 已在 C++11 弃用、C++17 移除，不要使用。

---

## 二、`unique_ptr`

独占所有权，不能拷贝，只能移动。几乎无额外开销。

```cpp
#include <memory>

std::unique_ptr<int> p = std::make_unique<int>(42);
// std::unique_ptr<int> q = p;          // 错误：不能拷贝
std::unique_ptr<int> q = std::move(p);   // 正确：所有权转移

if (q) {
    *q = 100;
}
q.reset();          // 释放并置空
int* raw = q.get(); // 只观察，不拥有
```

数组：

```cpp
std::unique_ptr<int[]> arr = std::make_unique<int[]>(10);
arr[0] = 1;
```

自定义删除器是 `unique_ptr` 类型的一部分：

```cpp
auto deleter = [](FILE* f) { if (f) fclose(f); };
std::unique_ptr<FILE, decltype(deleter)> fp(fopen("a.txt", "r"), deleter);
```

---

## 三、`shared_ptr`

共享所有权，内部有引用计数。每拷贝一次计数加一，析构一次减一，计数为 0 时释放对象。

```cpp
std::shared_ptr<int> sp = std::make_shared<int>(42);
std::shared_ptr<int> sp2 = sp; // 引用计数变为 2

std::cout << sp.use_count() << '\n'; // 2
```

优先使用 `std::make_shared`，异常安全且通常只分配一次内存。

```cpp
auto sp = std::make_shared<MyClass>(arg1, arg2);
```

注意：

- `shared_ptr` 的引用计数操作是线程安全的；
- 但同一个对象内容的读写不是线程安全的，仍需加锁；
- 同一个裸指针不要初始化多个 `shared_ptr`：

```cpp
int* raw = new int(1);
std::shared_ptr<int> a(raw);
std::shared_ptr<int> b(raw); // 错误：两个控制块，可能双重释放
```

- 多态删除时，基类析构函数必须是 `virtual`。

---

## 四、`weak_ptr`

`weak_ptr` 不增加强引用计数，不影响对象生命周期，用于观察 `shared_ptr` 或打破循环引用。

```cpp
std::shared_ptr<int> sp = std::make_shared<int>(42);
std::weak_ptr<int> wp = sp;

if (auto locked = wp.lock()) {
    std::cout << *locked << '\n'; // 对象仍存在
} else {
    std::cout << "对象已释放\n";
}
```

### 循环引用问题

```cpp
struct Node {
    std::shared_ptr<Node> next;
    std::weak_ptr<Node> prev; // 用 weak_ptr 避免循环引用
    ~Node() { std::cout << "~Node\n"; }
};

auto a = std::make_shared<Node>();
auto b = std::make_shared<Node>();

a->next = b;
b->prev = a; // 不增加强引用计数
```

如果 `prev` 也用 `shared_ptr`，`a` 和 `b` 会互相持有，导致引用计数永远不为 0，内存泄漏。

---

## 五、`enable_shared_from_this`

如果类内部需要返回自身的 `shared_ptr`，应继承 `std::enable_shared_from_this`：

```cpp
struct Foo : std::enable_shared_from_this<Foo> {
    std::shared_ptr<Foo> self() {
        return shared_from_this();
    }
};

auto f = std::make_shared<Foo>();
auto f2 = f->self();
```

不要写成 `std::shared_ptr<Foo>(this)`，否则会产生两个控制块，导致重复释放。  
注意：对象必须已经被 `shared_ptr` 管理后，才能调用 `shared_from_this()`。

---

## 六、常见使用建议

1. **默认用 `unique_ptr`**，只有确实需要共享所有权时才用 `shared_ptr`。
2. 观察但不拥有资源时，用裸指针、引用或 `weak_ptr`。
3. 函数参数：
   - 不涉及所有权：传 `T*` 或 `T&`；
   - 转移所有权：传 `std::unique_ptr<T>`；
   - 共享所有权：传 `std::shared_ptr<T>`。
4. 优先使用 `std::make_unique` 和 `std::make_shared`。
5. 不要用 `get()` 返回的裸指针去创建另一个智能指针。
6. 不要手动 `delete` 智能指针管理的对象。
7. 多态基类析构函数要声明为 `virtual`。

简单选择原则：

```cpp
独占资源      -> std::unique_ptr
共享资源      -> std::shared_ptr
观察/打破循环 -> std::weak_ptr
```
